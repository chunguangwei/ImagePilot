# EmbeddingGemma 多描述匹配（1.5.91）

## 实现

- 每个默认内置类别使用原完整说明及两个互补的视觉描述，覆盖人物自拍/全身像、真实婴幼儿、多人活动、网络机柜、奖杯等主体。文本仍使用现有官方 classification query 前缀。
- 每条描述先归一化，按类别等权求均值后再次归一化；图片与合并后的类别向量计算余弦相似度。避免仅一条宽泛描述匹配背景就凭最高分获胜。
- 用户自定义规则或类别说明仍是唯一引用，不额外追加内置通用原型。隐藏类别继续排除。模型、类别或规则变动会使文字向量缓存失效。
- 多描述编码仅在本批首次或类别变化时发生；每张照片仍只有一次图像编码，不下载额外模型，不调用外部 API。
- 候选无正相似度，或前两名差值小于 **0.005** 时不强行接受。不确定照片保留原类别；原本待分类的继续待分类，并保存候选供查看。它是保守的初始拒判策略，不是概率校准，也不能保证所有错分被拦住。
- 写入成功后才计入不确定数量；不确定项不计入成功分类数。元数据记录 `prototype-centroid-v1`、领先幅度、判定带和原因。

## 原生六图对照

使用隔离 iOS 模拟器中的官方图文模型与既有六张回归图，比较 1.5.90 基线、直接取最高分、合并类别向量及最高两分均值。开发脚本 `scripts/embedding-prototypes-smoke.js` 不进入正式入口。完整数值见 [对照结果](embedding-prototypes-1591-results.json)。

**基线和最终方案均为 6/6，不能宣称总体准确率已提高。** 直接取多描述最高分时，食物与艺术的领先幅度降至约 0.002；合并原型约为 0.020，避免了这个具体退化。相对基线也有类别领先幅度变小，不能把分差增加当作普遍结论。

最终生产函数再次独立编码并运行，六图均接受且符合预期。初次对照文字编码约 3.2 秒（该模拟器数据，不代表手机速度）。没有用这六图估计实际照片总体准确率，也没有完成设备人群的大样本阈值校准。

## 验证边界

自动测试覆盖规则优先、文本变化失效、原型融合、近似并列、不确定保持类别及落库失败计数；还需要用户实际相册验证儿童/卡通、人物/穿搭、风景/背景人物等混淆。若不确定项增多，优先手动确认或主动切换 LFM/E2B，不自动调用另一模型。
