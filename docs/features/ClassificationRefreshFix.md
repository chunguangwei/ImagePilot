# 分类与删除照片后的刷新修复

2026-11-06；随 1.5.91 提供。

## 用户可见问题与原因

1. 分类显示成功，但对应目录没有及时更新。分类服务把结果写入数据库时普遍关闭缓存更新；开启缓存更新的旧实现只调用 `buildCache()`，缓存已加载时直接返回旧数据。进度刷新依赖每 20 张或任务结束，目录页也未订阅缓存变化。
2. 安卓手机外部删除照片后，点击首页圆圈扫描仍显示旧照片。原生扫描已从数据库删除记录，但 JS 遇到“无新增照片”直接返回，没有刷新缓存。冷启动重新读取数据库才恢复正确显示。

## 修复

- 分类结果写入成功后，按已持久化字段增量更新缓存，同步分类统计、描述与近期照片引用，一次通知订阅者。既有手工分类等其他调用语义保持原样。
- 只有全部写入成功、ID 可定位、类别语义明确时才发布增量结果。部分成功、URI-only 或空类别回读数据库，避免推测哪些记录成功。
- LFM 每张成功结果立即发布；EmbeddingGemma/E2B 已有逐张落库路径同步发布。传统模型及在线批处理仍以原有落库批次为边界，成功落库就通知，不等额外的 20 张阈值。
- 首页、当前目录订阅缓存更新，250ms 内合并事件；持续更新不会无限推迟刷新，已有加载结束后处理期间积累的更新，离开页面取消订阅和待执行计时器。目录后台更新不闪整页加载动画。
- Android 无新增扫描也经过完成阶段，先刷新数据库缓存再通知界面；无进度回调的服务调用也刷新缓存。
- 首页扫描收尾直接重建缓存、重载视图，不调用带忙碌守卫的下拉刷新函数。

## 验证

修复前测试复现：已保存类别未进入缓存，描述未同步，无新增扫描未刷新缓存。

修复后：`npm test -- --runInBand --testPathPattern='src/.*__tests__/.*test'` 共 22 套、152 项通过；Android/iOS 完整生产 JS bundle 成功。新增覆盖暖缓存分类统计和描述、近期照片、失败写入、部分成功、URI-only、空类别、保持原 URI、无新增扫描、持续事件合并、异步加载期间的新事件及取消订阅。

尚未执行此次改动的手机真机验证；Android 删除同步依赖原生扫描已识别删除记录，本次不改变相册权限或原生文件删除行为。

## 补充：手动调整分类

手动移动完整成功才增量发布；部分成功回读实际记录，失败不再只改内存。预览页检查写入结果，采用实际类别（包括视频退回 NA_video），并更新滑动列表。批量改类不再提交前从所有视图强行移除图片，而按当前类别、时间或文件夹筛选重载；超时不再提示“大概率成功、重启验证”。
