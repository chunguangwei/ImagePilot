# 描述优先联合分类试验

状态：随 v1.5.89 提供用户测试，不修改 v1.5.88 标签或历史发行说明。Android/iOS 共用调度器；尚未在用户 Android 真机上验证联合输入。

## 行为

- 描述关闭：原图对全部有效系统/自定义类别说明与规则做相似度分类，不调用 LFM。
- 描述开启：每批最多 8 张先生成主体和场景短语；40 token 输出上限，中文提示约15字/英文约8–12词，属于生成目标，并非保证。按完整短句保留最多两段，去除引号文字、阿拉伯数字和明显转录句；这不能修正物体识别错误。
- 描述保存后释放 LFM；EmbeddingGemma 同时接收原图和短描述，匹配全部类别语义。额外计算原图结果用于诊断，没有用人工权重混合分数，也没有把相似度当准确率。
- 描述失败按原图分类，留下描述失败状态；联合嵌入失败保留原图分类，classification=fallback，可从首页重试，不必再次生成描述。
- 已有 message 保留。新的模型短描述写入 embedding.caption.text，手工文本和旧 OCR 型描述不直接作为联合输入。来源以 URI+文件大小校验；同 URI、同大小的原地内容修改无法被此校验发现。
- 两阶段分别持久化；只有分类完成才置 classification=complete。NA 图片仍由待分类入口发现；已分类但流程未完成的图片由首页继续离线处理恢复。
- 忽略具体文字不等于完全去除文字视觉特征。图片仍含原始像素；模型也仍会幻觉物体或文字。

## 目前验证

- 6 张独立图：机柜、奖杯、人像、猫、咖啡、合影。试验原生联合输入与原图结果均为对应预期类别，尚未证明准确率提升。
- 同机 iOS 模拟器、同图顺序的描述阶段：短提示/40 token 总计14672ms，旧提示/160 token 总计15099ms；平均原始输出约27.2字、35.3字。单轮小样本、含模型加载、缓存和采样影响，约3%差异不足以证明稳定提速。该数据不含联合分类的额外开销，也不代表安卓真机速度。
- 16 个自动测试套件、117 项测试全部通过；Android/iOS 完整 JS bundle 构建通过（不等于安卓真机验证）。
- 隔离 iOS 模拟器真实模型与数据库续跑验证通过：先保存8张描述后中断（0张完成分类），恢复后新增4张描述、完成12张联合分类，描述/分类/联合回退失败数均为0；全部记录保留来源标记。
- 自动测试覆盖开关、描述先于分类落库、手工描述保留、描述失败回退、联合失败恢复、两阶段停止续跑、模型串行释放。
- 开发原生脚本：scripts/caption-first-smoke.js，要求隔离模拟器 Documents 中放置 rack/trophy/portrait/cat/food/group.jpg 和官方模型。脚本生成12个独立记录（6图各两份），第8张描述保存后停止，再恢复。不得用该脚本打包正式应用。

## 后续验证

使用 v1.5.89 测试版方案，以更广泛的实际照片比较纯图/联合分类的正确率、描述内容、整体耗时和温升。不能仅因为联合相似度更高就认为分类更准确。

模型组合输入依据：[Google 官方多模态嵌入说明](https://ai.google.dev/gemma/docs/embeddinggemma/multimodal-embeddinggemma-with-sentence-transformers)。官方支持组合输入不构成此应用方案准确率提升的证据。
