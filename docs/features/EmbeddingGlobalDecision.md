# 全局子类型判别（1.5.95）

## 审查与范围

统一审查EmbeddingGemma的类别文本、缓存、打分、接受条件、自定义规则及结果保存，不针对植物/电子产品设置例外。全局21个内置类别分为58个视觉子类型，每个子类型两条同义描述。不同子类型是替代选项，不能再把其向量全部平均；例如网络设备不必同时匹配手机或相机。候选包括全部有效内置和自定义分类，排除待分类桶和已隐藏类别，沿用现有清单逻辑。

自定义规则或配置描述优先，只编码原始规则，不附加内置子类型；EmbeddingGemma仍是语义匹配，不能保证精确执行计数、否定或组合逻辑。E2B和在线模型入口不变，未引入新下载模型。

## 两种视角

1. 同一子类型内平均两条同义描述的相似度；父分类取最佳子类型分数，不被其他外观拉低。领先幅度比较不同父类，不让同类子类型互相竞争。
2. 保留原有整体描述/v3一致性判别作为另一视角。两种明确结论相互冲突时拒判。
3. 子类型明确、整体视角不确定时，采用子类型。子类型间隔不足，但其首选与整体明确首选相同，则使用整体视角的分数和间隔。两者都不明确时拒判。
4. 不降低0.005初始间隔，不转成概率；拒判保留原类别或待分类。不存在指定某类必须赢的逻辑。

版本subtype-consensus-v2（自定义扩展；内置七图记录来自等价的v1内置判别）。诊断增加decisionMethod、groupedMargin、legacyCategory、legacyRejectionReason及各子类型实际文本/分数；每个候选的similarity来自最终使用的同一视角，legacySimilarity/groupedSimilarity分开保存。旧算法结果仍提示重分类。

## 性能成本

默认21类首轮最多编码179条文本（原63+子类型116），相同文本去重。批内缓存全部向量，缓存键包含模型路径、类别及所有实际文本/分组；改规则会重建。每张图片仍一次图像编码。结束扫描dispose后清空缓存，下轮首张仍需准备，不宣称首张更快。

全量诊断文本/分数占用较前版增加；大图库的存储、缓存占用及Android实际吞吐仍需测量，后续可独立做诊断按需保存/去重，不能忽略此成本。

## 验证结果与限制

- 230项应用测试通过：全部内置分组、自定义规则不被绕过、同类子类型不拉低分数、不参与父类间隔竞争、明确冲突拒判、同类回退、缓存和图像推理次数等。
- 隔离iOS模拟器对七张样本做真实原生推理，覆盖电子产品、艺术、单人、宠物、食物、社交六类；候选清单为全部21类。纯子类型方案只接受5/7（人物、合影变模糊），因此没有直接采用。最终组合方案接受7/7且与人工预期一致，与旧方案7/7持平。
- 食物子类型间隔约0.0520，旧整体间隔约0.0202；不同打分方法的间隔不能直接等同准确率改善。人物和合影由同类整体视角补充确认。
- 本次模拟器生产链路首张约8.18秒，后续约0.21–0.22秒；包含文本准备和模型重载，且模型文件缓存已预热，不能作为Android真机速度承诺。
- 数字记录见embedding-grouped-results.json，未提交照片。类别子类型数量不等、类别语义重叠和0.005未校准阈值仍可能影响结果，需更广样本验证。不能把六类七图对照称为所有分类精度已提升。
- 用户Android机柜v2诊断没有新子类型向量，不能用旧分数推算此次机柜结果。仍需新版本真机分类与诊断验证。
