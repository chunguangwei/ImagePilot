# 最强具体描述冲突检查（未发布）

## 真实 Android 诊断

用户在1.5.94重新分类网络机柜，算法prototype-consensus-v2仍accepted=true、plants。实际提示词齐全，不能再把这次误判解释为旧分类记录或未加载机柜提示词。

| 证据 | 植物 | 电子产品 |
| --- | --- | --- |
| 归一化类别均值相似度 | 0.6742551879 | 0.6601617596 |
| 最佳两描述平均 | 0.6690400632 | 0.6527781321 |
| 最强单条描述 | 0.6735974713 | 0.6781019019 |

电子产品的机柜描述是全部21类逐描述分数中的最高分，手机/相机/电路板两条描述只有0.6274543622、0.6250481152。把不同外观的替代例子平均，会稀释具体机柜证据；v2的两项检查都依赖这种聚合，无法检测该冲突。此证据确定了决策缺口，不证明模型总体正确或已经解释所有Android/iOS差异。

## 改动

prototype-consensus-v3保留现有排序、双证据检查及0.005阈值，再检查全部候选中最强单条描述是否仍属于拟接受的类别。属于其他类别或跨类别并列最高时，返回strongest-prototype-disagreement，不自动改类；保留旧类或待分类，界面显示本次未自动改类。不会把最强单条描述的类别直接提升为答案。

本样本电子具体描述仅领先植物0.0045044306，低于现有0.005门槛；不为单张样本降阈值或硬编码电子产品。该检查是保守拒判，可能增加人工确认，不能宣称直接纠正全部分类。

诊断增加strongestCategory、strongestMargin。复用已算出的逐描述分数，不增加文本/图片模型调用，不修改类别规则、模型权重、已有照片或描述。旧算法结果仍提示重新分类。

## 验证

真实Android分数回归：修复前得到null rejectionReason（错误接受）；修复后strongest-prototype-disagreement，最强类别electronics。测试还覆盖最强分数跨类别并列、明确一致时接受、自定义单规则，以及过宽单例不得强行选择另一类别。

已有七张iOS原生样本中maximum、centroid、topTwo的类别赢家均一致且已有两项间隔达标，新拒判规则不改变这些样本的接受结论。这是已记录分数回放，不是新的Android真机分类验证。

本变更未打包发布，线上仍为1.5.94。

后续开发将此v3检查保留为全局子类型方案的整体视角，详见[统一判别](EmbeddingGlobalDecision.md)；该文记录的v3是中间方案，不是最新开发默认算法。
