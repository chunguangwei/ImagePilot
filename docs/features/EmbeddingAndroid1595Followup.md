# 1.5.95 Android 机柜诊断复盘（1.5.96修正）

用户在1.5.95重新分类后，subtype-consensus-v2仍接受plants。实际子类型分数：plants/potted 0.6891738180279177、architecture/interior 0.6800176431488831、electronics/network 0.6648403530476786。旧视角已因最强原始参考属于electronics而拒绝plants，但selectGroupedDecision允许新的子类型视角重新接受该类别。

1.5.96的subtype-consensus-v3保留该冲突拦截：旧视角报告strongest-prototype-disagreement时，子类型不能接受与最强参考不同的父类别；若明确选择最强参考的父类别，仍检查正常领先幅度及排除对象；最强参考跨类别同分也保持不确定。不为植物、电子设备或任何自定义ID设置特殊权重。

真实分数回放由接受plants改为拒绝自动改类。**这不是正确识别electronics的证明**。按用户后续要求，1.5.96完成推理但不确定时归入“其他”。普通扫描只处理待分类；主动重分类会把原有错误类别改为“其他”。已有描述保留。

此改动收紧策略，孤立的过强参考也可能导致拒判，接受率可能下降。既有“允许子类型覆盖孤立最强参考”的测试已明确改为保留冲突，与新策略一致。冲突拦截初版243项/32套测试通过，随后新增双端归入“其他”、异常不写入、目录计数刷新和显示名兼容测试；最终验证见发布记录。发布目标为1.5.96/v3，实际构建和分发验证见对应发布记录。

两端代码都配置CPU双线程、70视觉token，JS共用768边长预处理；Android原生转PNG再交给SDK，iOS直接传入预处理文件的字节。尚未验证图像解码、SDK版本、模型文件和实际张量的逐项一致性，不能从这条日志判断根因是PNG转换或模型能力。iOS七图结果不能作为Android准确率证明。
