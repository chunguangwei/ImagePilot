# 内置分类规则编辑与旧数据保护（1.6.2）

## 更新文案

- 设置中的“分类与规则”支持编辑内置分类规则，补充画面场景和排除条件，并可恢复默认规则。
- 强化主要拍摄对象的区分：以人物为主体的户外写真归人物类，整体环境为主体、人物只是远处点缀的画面可归风景。
- 修改规则只影响后续分类或用户主动选择的重新分类，不自动改动已有照片的分类。
- 分类备份包含用户修改的内置规则；恢复时保留本机已有规则，旧备份继续兼容。
- 加强旧数据库迁移和 iOS 扫描读取失败时的数据保护。

## 实现与兼容性边界

规则存储在可选的 `aiProvider.builtinCategoryRules` 设置字段中，不改变内置分类 ID、照片记录或用户原有自定义分类。恢复默认只移除当前类别的规则覆盖。保存未修改的默认说明也不会替换默认的多个视觉描述。

Gemma 2、E2B 和当前在线分类流程读取这些规则。固定标签的小模型无法理解用户输入的自然语言规则，界面已说明。主体描述属于语义引导，不是人物检测器或绝对排除保证。最高有效类别分数策略、0.5 低分回退阈值及 140 视觉 token 保持不变。

正常扫描按照片 ID 合并并保留已有分类、描述、置信度和检测信息。修复两条原有异常路径：读取已有记录失败时停止扫描写入；旧数据库先补拍摄参数列，再创建依赖这些列的索引。没有证据表明用户已经因这些路径丢失数据。

审查了 App Store 标签 `ios-appstore-1.5.74-b6`（b6c1280）；其数据库已有相关拍摄参数列。不能据此证明这是绝对最早的商店版本，也未执行最早商店安装包到当前代码的真机升级。历史 `tobecleaned` 暂存箱迁移、用户主动重新分类、删除及备份恢复仍按原有行为运行，不能笼统承诺所有操作都不改变分类。

## 验证

- `npx jest src --runInBand --silent`：44 套件、309 项通过，包括规则保存失败保留草稿、恢复默认、在线规则、自定义规则保留和扫描读取失败禁止写入。
- `python3 scripts/test/legacy-sqlite-migration.py`：模拟缺少拍摄参数列的旧库，连续执行两次迁移，分类、描述和检测字段保持不变。此测试验证 SQL 顺序，不替代旧商店版本真机升级测试。
- iOS 模拟器 140 token 本地推理：湖景→旅行风景 0.7455，机柜→电子产品 0.7322，奖杯→艺术 0.7017，合影→社交活动 0.6808。除机柜外使用截图中的照片区域；未增加户外人像样本，不能据此宣称人物边界已全面解决。
- 完整模型回归结果：`docs/experiments/primary-subject-rules-20261107.json`。
